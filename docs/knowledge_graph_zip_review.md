# Knowledge Graph Zip Review

Source inspected locally: `Knowledge Graph.zip`

## Summary

The archive contains True Demand / SC4EU knowledge graph assets, MPC survey transformation code, generated Turtle graphs, and Docker/Fuseki deployment examples.

The current KGQA project already uses a local RDF graph:

- `data/infineon/graph.ttl`
- `data/infineon/ontology.ttl`
- `data/infineon/schema.json`

The archive's top-level `Knowledge Graph/complete_vehicle_knowledge_graph.ttl` has the same triple count as the current repository graph (`1,159,883` triples), so it appears to be the same or a very close version of the graph already used by the KGQA pipeline.

### Fuseki Deployment

Relevant deployment files:

- `docker-compose.yml`
- `Dockerfile`
- `Dockerfile.fuseki`
- `entrypoint.sh`
- `shiro.ini`

The architecture is:

1. Fuseki container exposes a SPARQL dataset.
2. Transformer/API container watches or receives Excel files.
3. Transformer creates a Turtle KG.
4. Transformer uploads the Turtle graph to Fuseki.

The current KGQA app does not use Fuseki yet. It loads `data/infineon/graph.ttl` locally using `rdflib`. Fuseki is therefore optional for the current thesis prototype, but useful if the system needs a production-like SPARQL endpoint.

## Security Notes

The archive contains session password files, private key files, nested `.git` metadata, and hardcoded Fuseki credentials in Docker/Fuseki examples.

Do not commit these files to this repository.

If any Fuseki setup is reused, credentials should be moved to environment variables or a local `.env` file that is ignored by Git.

## Recommended Use

Use now:

- Treat `complete_vehicle_knowledge_graph.ttl` as a reference version to compare against `data/infineon/graph.ttl`.
- Use the transformer scripts as provenance/reference material for explaining how the KG is generated from survey/Excel data.
- Use the Fuseki Docker files as a deployment reference, not as-is.

Do not use directly yet:

- Session password/private key files.
- Nested `.git` directories.
- Hardcoded credentials.
- Large Excel/raw generated files inside the KGQA repo unless explicitly needed.

Potential future integration:

- Add optional SPARQL endpoint execution mode to the KGQA pipeline.
- Keep the existing local `rdflib` mode as default for reproducible thesis evaluation.
- Add a sanitized Fuseki deployment template under `deploy/fuseki/` only if production-style deployment becomes a requirement.
